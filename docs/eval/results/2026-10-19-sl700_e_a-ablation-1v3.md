## Caveats

- **The agent produced no items.** Model-on reported and surfaced exactly the same 97 items as model-off: same signatures and lanes, all adjudicated. Every recall, precision, noise and citation metric is therefore identical by construction. The ablation measures the agent's own activity and cost, not a change in findings.
- One run per arm. The model is stochastic, so there is no variance estimate for model-on, and n = 22 observable opportunities.
- Agent output quality was the limiting factor:
  - 21 of 44 model calls were invalid;
  - 10 of 12 cases ended in deterministic fallback parking with an analyst flag, and the other 2 exhausted their budget;
  - no seed was concluded;
  - no escalation was accepted.
- **Pivot reach** means a pivot retrieved a gold action/outcome record. That is reach, not a finding, and it does not count toward recall. All four opportunities reached that way had already been surfaced by the sweep.
- Reach at the entity + window level (Tier B style) is loose, because the executed pivots used windows of up to several hours.
- **Timing:** the +1.7 s change in time to first actionable is sweep-timing noise, since the agent phase starts after the sweep. The +508.6 s is the agent phase.
- **Records returned** in the model-on run include the 8 pivot tasks.
- **Review order:** the model-on hunt has no report-manifest revision, so its review order is the replicated manifest sort. The key is the same as run 1's, and the item set and order are identical.
- **Pivot retrieval attribution is a lower bound.** It combines the event IDs in each step's result digest (at most about 50 per pivot) with raw records whose *first* retrieving task was the pivot. Records already retained by an earlier hunt cannot be attributed, because `raw_record` is not hunt-scoped.
