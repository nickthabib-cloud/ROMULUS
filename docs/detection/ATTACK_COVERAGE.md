# ATT&CK Enterprise detection coverage

Generated from vendored ATT&CK Enterprise 20.0 and ROMULUS `pack@33`.
This file is generated by `python scripts/coverage_matrix.py`; do not edit it by hand.

Coverage is based only on explicit typed rule metadata. Parent mappings do not imply sub-technique coverage.
Full-search rules read fields that record every occurrence they look for; the matrix describes rule
capability, not what any hunt searched. ROMULUS reports what it finds and never claims that nothing is there.

To keep the matrix readable, 398 uncovered sub-techniques are collapsed under their parent rows.
Every collapsed id and name remains listed and is marked not covered.

## Strength legend

- **full-search** — A covering rule reads fields that record every occurrence it looks for, so a hunt reports 'searched in full' when every partition in scope was evaluated. That is a statement about the search, never that the ATT&CK technique is absent.
- **positive-only** — A covering rule reports matching evidence; a non-match says nothing about what was not seen.
- **context-only** — A covering rule provides investigation context around other findings.
- **none** — No active rule explicitly maps to the technique.

A technique's strength is the strongest strength among its active covering rules.
Each row therefore shows the strongest covering rule's strength; the covering-rules cell shows every rule's own strength.
