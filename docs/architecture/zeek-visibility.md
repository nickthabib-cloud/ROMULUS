# Zeek visibility and evidence links

Zeek health is a coverage input and never a detection. Canonical, deduplicated sweep events supply connection services, activity spans and content gaps exactly once, including the connection lookback. Sensor/family/time counters live on a 15-minute grid in SQLite. Visibility has its own disk allowance and cannot consume detector state. Source collection and final coverage run after findings have been published. A refused page, source error or visibility state limit is named as incomplete.

`site/collection.yaml` may include:

```yaml
zeek:
  capture_loss_threshold_pct: 1.0
  connection_lookback_hours: 24
  # Set only after verifying this deployment's stats logging cadence:
  stats_interval_seconds: 300
  plain_sources:
    native-zeek-json:
      sensor: sensor-east
      # Optional; otherwise each record must carry a catalogued _path:
      log: conn
```

Omitting `zeek` preserves the site's previous canonical digest. A native target must be declared explicitly; `_path` or a plausible index name does not establish that it contains Zeek. The declaration is applied before the source profile freezes its role and identity, and survives resume through the frozen site digest. Native `ts` ranges use epoch seconds. Fixed log names resolve through the catalog; `conn_long` retains its interim semantics.

A `capture_loss` row covers `[ts-ts_delta, ts)`. Every positive loss measurement is retained as a caveat. Positive loss at or above the configured threshold, or missing health during any data activity, makes every rule reading a Zeek family searched in part for that sensor and interval, including families whose analyzer wrote no records. Each rule has one cell per sensor, referencing the full interval appendix. Healthy sensors stay complete, and health-only sensors create no partial cell. Zeek's guidance that loss below one percent is tolerable motivates the default threshold; it does not make sub-threshold loss invisible. Data without interval health is searched in part; health without data creates no such claim. Health interval-end retrieval has a bounded 24-hour lookahead to include straddling intervals.

`stats` packet counts are already interval deltas. A packet-drop estimate uses the row's dropped/link counts; it is not TCP capture loss. Native stats rows do not declare duration. A verified deployment cadence and complete scoped retrieval establish the first row's interval as [timestamp minus cadence, timestamp). Later same-worker timestamps must match the cadence within the larger of one second or ten percent of cadence, allowing ordinary timer jitter. Actual adjacent timestamp bounds are used. Every observed worker must cover the interval; another worker's measurements cannot conceal a gap. Existing health rows with unreadable measurement fields are named as health unreadable. Missing rows, workers, counters or cadence leave interval health unknown. Worker percentages are never averaged. Security Onion 2.4 excludes `capture_loss` and `stats` from its default Zeek indexing collection; ordinary network rows from that delivery correctly report missing health. Custom deployments can declare a separate native health target. Malcolm diagnostic metrics whose source fields are not verified remain not assessed.

Connections use a conn-only start lookback, with an end-time or duration overlap superset predicate where the source supports one. Missing end measurements remain eligible; a final conn without duration is zero-length, while an interim without an end remains unresolved. A complete zero-document source profile avoids that work; every nonempty, unknown or capped profile retains retrieval because dataset terms can omit rows using another supported shipper marker. Newly observed connections trigger retrieval even after an empty profile. Visibility state is allocated only after actual Zeek records are observed. Every canonical connection contributes its clipped start-to-end activity span to the 15-minute grid, including connections starting inside the hunt, so later loss or missing health remains visible. Record and service counts are attributed once to the first overlapping interval; activity extends across every overlapping interval. Adjacent intervals with identical health statements merge, bounding snapshot rows by sensors, families and intervals instead of connection count. Exact half-open interval overlap determines inclusion, so a connection ending exactly at the hunt start is out. Malcolm's verified cumulative `lastPacket` plus interim flag can recover an older open connection. Elastic, Security Onion and plain connections beginning before the configured lookback are not evaluated; deployments without the Malcolm predicate cannot establish older interim coverage. Selective sensor/UID lookups resolve interim records before any rule consumes their cumulative counters. Final records take precedence; otherwise the largest cumulative duration is used with explicitly named write-order uncertainty. Disk tombstones prevent later partitions or targets consuming the same connection twice. This preserves the rules' existing publication timing. If canonical identity state is refused at the shared disk ceiling, cumulative flow aggregates stop consuming those records and name the withheld counts. Direct rules remain eligible. Indicator matching uses its bounded single-record fallback, cites the actual record and leaves retained group counts unchanged; it never invents a connection total from uncertain duplicates.

Analyzer coverage counts services from the sweep's canonical connections, including every service in a multi-service row, without keeping a second per-UID inventory. A final row with an empty service list still supersedes interim service claims. Analyzer presence is checked by log identity: RFB does not satisfy RDP, while SMB and LDAP keep their respective log groups. Per-log targets without conn records do not require conn fields. Shipper source predicates keep Filebeat and Security Onion records separate. Marker predicates resolve exact-searchable fields and reported multi-fields through one shared helper. An observed or profile-verified Zeek target without exact markers is named as unresolved for visibility and lookback. An analyzer-absence statement requires complete exact retrieval across every relevant target; incomplete inventory yields presence unresolved. Unrelated targets carrying only unused shared mappings do not create Zeek partiality. Unambiguous Elastic dataset-only names come from the normalizer's existing catalog-derived recognition set, while ambiguous names still require shipper markers. Missing analyzer rows and content-gap counts are separate statements. Missing connection bytes, history `g`/`x`, and missing/overflow/timed-out file bytes attach cited supporting-record notes to findings without lowering priority or changing the globally stable normalized event. File-only findings follow the file record to its carrying connection. Linked, pivot and context publication use bounded, already fetched witnesses and retain the clean file record that establishes a carrier edge; a missing carrying connection is named as not assessed.

Observed `zeek_uid` joins use sensor plus UID and the connection span with one minute before start for modest clock skew and five minutes after end for log-write lag. Observed `zeek_file` joins follow the file ID through files, PE/x509 records and every carrying connection, including older `conn_uids` arrays. Observed `certificate` joins use only the first leaf fingerprint and a 30-day lookback because x509 records can be deduplicated; unresolved details say “certificate details not in scope.” Inferred `address_host` joins are hypotheses, require a DHCP lease covering the anchor in `[start,end)`, and cite an actual host-telemetry witness. Overlapping conflicting hosts or MACs remain unresolved with both leases cited. DHCP lookback is seven days. Host telemetry is a separate existence probe retaining at most ten nearest records in descending time order, through five minutes after the anchor. Probe overflow does not make the lease hypothesis partial. Dedicated host links own full activity searches and direct detection; the witness does not run the direct pack.

Each dependent link, including every anchor-key variant, shares limits of 10,000 fetched rows, 1,000 join keys and 128 physical source queries; lower expansion query and wall-clock limits apply. Reaching a limit names the unresolved work. A relevant target with unsearchable source markers, sensor or join key remains named as unresolved even when another target succeeds; this applies to links, canonical connection selection and content-gap lookups. These links never count as model-agent reach. Only Zeek anchors receive the extra expansion slots.

Only low-cardinality health composites remain. They are sliced to sweep time partitions, with a default cap of 32 pages and a 30-second deadline per composite; ordinary partition health fits one 1,000-bucket page, while the cap admits larger sensor fleets without unbounded repeated collection. `ROMULUS_ZEEK_VISIBILITY_MAX_PAGES`, `ROMULUS_ZEEK_VISIBILITY_DEADLINE_SECONDS` and the separate 256 MiB `ROMULUS_ZEEK_VISIBILITY_DISK_MB` allowance configure these limits. Exhaustion makes visibility partial and leaves detection state eligible.

Detailed visibility is frozen once as a content-addressed immutable snapshot. Rows commit in chunks of 256 before a single atomic publication record exposes the complete snapshot, so streaming does not hold an unbounded write transaction. Rule cells reference that snapshot with sensor/family selectors. The JSON manifest holds the descriptor and an explicit bounded preview. Report bundles include the complete hash-verified JSONL artifact, Markdown streams every statement, DOCX identifies the preview count and full appendix, and the authenticated web view exposes the complete artifact. Reopening the repository and JSON-roundtripping the manifest does not require the temporary sweep stage.
