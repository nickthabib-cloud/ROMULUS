# Zeek visibility and evidence links

Zeek health is a coverage input and never a detection. The hunt joins source-owned composite aggregates across all targets before stating sensor visibility or missing analyzer content. Sensor/family/time state, canonical connection identities and counts live in SQLite under the hunt's shared state budget. A refused page, source error or state limit is named as incomplete.

`site/collection.yaml` may include:

```yaml
zeek:
  capture_loss_threshold_pct: 1.0
  connection_lookback_hours: 24
  # Set only after verifying this deployment's stats logging cadence:
  stats_interval_seconds: 300
  plain_sources:
    native-zeek-json:
      sensor: sensor-east
      # Optional; otherwise each record must carry a catalogued _path:
      log: conn
```

Omitting `zeek` preserves the site's previous canonical digest. A native target must be declared explicitly; `_path` or a plausible index name does not establish that it contains Zeek. The declaration is applied before the source profile freezes its role and identity, and survives resume through the frozen site digest. Native `ts` ranges use epoch seconds. Fixed log names resolve through the catalog; `conn_long` retains its interim semantics.

A `capture_loss` row covers `[ts-ts_delta, ts)`. Every positive loss measurement is retained as a caveat. Loss at or above the configured threshold makes only the affected sensor/family intervals searched in part. Zeek's guidance that loss below one percent is tolerable motivates the default threshold; it does not make sub-threshold loss invisible. Data without interval health is searched in part; health without data creates no such claim. Health interval-end retrieval has a bounded 24-hour lookahead to include straddling intervals.

`stats` packet counts are already interval deltas. A packet-drop estimate uses the row's dropped/link counts; it is not TCP capture loss. Native stats rows do not declare duration. A verified deployment cadence, complete scoped retrieval and adjacent same-worker timestamps matching that cadence are required before an interval can be derived. Actual timestamp bounds are used. Missing rows, workers, counters or cadence leave interval health unknown. Worker percentages are never averaged. Security Onion 2.4 excludes `capture_loss` and `stats` from its default Zeek indexing collection; ordinary network rows from that delivery correctly report missing health. Custom deployments can declare a separate native health target. Malcolm diagnostic metrics whose source fields are not verified remain not assessed.

Connections use a conn-only start lookback. A complete zero-document source profile avoids that work; every nonempty, unknown or capped profile retains retrieval because dataset terms can omit rows using another supported shipper marker. Newly observed connections trigger retrieval even after an empty profile. Visibility state is allocated only after actual Zeek records are observed. Every canonical connection contributes its clipped start-to-end activity span, including connections starting inside the hunt, so later loss or missing health remains visible. Exact half-open interval overlap determines inclusion, so a connection ending exactly at the hunt start is out. Malcolm's verified cumulative `lastPacket` plus interim flag can recover an older open connection; deployments without that predicate cannot establish older interim coverage. Selective sensor/UID lookups resolve interim records before any rule consumes their cumulative counters. Final records take precedence; otherwise the largest cumulative duration is used with explicitly named write-order uncertainty. Disk tombstones prevent later partitions or targets consuming the same connection twice. This preserves the rules' existing publication timing. If canonical identity state is refused at the shared disk ceiling, cumulative flow aggregates stop consuming those records and name the withheld counts. Direct rules remain eligible. Indicator matching uses its bounded single-record fallback, cites the actual record and leaves retained group counts unchanged; it never invents a connection total from uncertain duplicates.

Analyzer coverage counts canonical sensor/UID service identities, including every service in a multi-service row. A final row with an empty service list still supersedes interim service claims. Analyzer presence is checked by log identity: RFB does not satisfy RDP, while SMB and LDAP keep their respective log groups. Per-log targets without conn records do not require conn fields. Shipper source predicates keep Filebeat and Security Onion records separate. Mixed Elastic targets aggregate both dataset markers, choosing each bucket's event dataset before its stream fallback; mapped-but-missing alternatives do not discard activity or count it twice. Unambiguous Elastic dataset-only names come from the normalizer's existing catalog-derived recognition set, while ambiguous names still require shipper markers. Missing analyzer rows and content-gap counts are separate statements. Missing connection bytes, history `g`/`x`, and missing/overflow/timed-out file bytes attach cited supporting-record notes to findings without lowering priority or changing the globally stable normalized event. File-only findings follow the file record to its carrying connection. Linked, pivot and context publication use bounded, already fetched witnesses and retain the clean file record that establishes a carrier edge; a missing carrying connection is named as not assessed.

Observed `zeek_uid` joins use sensor plus UID and the connection span with one minute before start for modest clock skew and five minutes after end for log-write lag. Observed `zeek_file` joins follow the file ID through files, PE/x509 records and every carrying connection, including older `conn_uids` arrays. Observed `certificate` joins use only the first leaf fingerprint and a 30-day lookback because x509 records can be deduplicated; unresolved details say “certificate details not in scope.” Inferred `address_host` joins are hypotheses, require a DHCP lease covering the anchor in `[start,end)`, and cite an actual host-telemetry witness. Overlapping conflicting hosts or MACs remain unresolved with both leases cited. DHCP lookback is seven days.

Each dependent link shares limits of 10,000 fetched rows, 1,000 join keys and 128 physical source queries; lower expansion query and wall-clock limits apply. Reaching a limit names the unresolved work. A relevant target with unsearchable source markers, sensor or join key remains named as unresolved even when another target succeeds; this applies to links, canonical connection selection and content-gap lookups. These links never count as model-agent reach. Only Zeek anchors receive the extra expansion slots.

Detailed visibility is frozen once as a content-addressed immutable snapshot. Rule cells reference that snapshot with sensor/family selectors. The JSON manifest holds the descriptor and an explicit bounded preview. Report bundles include the complete hash-verified JSONL artifact, Markdown streams every statement, DOCX identifies the preview count and full appendix, and the authenticated web view exposes the complete artifact. Reopening the repository and JSON-roundtripping the manifest does not require the temporary sweep stage.
